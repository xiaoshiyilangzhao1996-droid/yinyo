# AGENTS.md — YINYO 开发宪章

以下是铁律，不是建议。每一条背后都有事故。

## 验证优先

- **写代码前读现有代码** — 不凭想象，不凭"应该有"。
- **用工具前查文档** — 不猜参数，不试错式调 API。
- **引用包前上 PyPI/GitHub 确认** — 🔴 血训：`agentmemory` 包不存在，凭印象写进 Spec = 伪代码。**任何"某包有 N stars/功能"的 claim 必须先验证。**

## Spec = 代码

- 每次重大变更后生成新 `yinyo-spec-vX.Y.md` 到 `tmp/`。
- 代码和 Spec 不一致 = 技术债，不是"后续补"。
- 变更日志精确到文件 + 行数，不做模糊描述。

## 不自审

- 写完代码后委托**独立子 Agent 盲测审计**。
- 盲测 Agent 只给 CLI 用法 + 测试套件，**不给源码**。
- 🔴 血训：v2.1 自审 → 48.9% 通过率；v3.0+ 独立盲审 → 100%。
- 审计后立即修复所有发现的问题，不等"下次再说"。

## 产品视角

- 设计从**产品板块**出发（用户画像、记忆体系、交互形态），不是技术组件堆砌。
- 🔴 血训：v5.0 前从"Agent Loop/Context/Evidence"角度设计，漏了 USER.md/MEMORY.md/AGENTS.md 三个认知层核心文件。补了 v6.0 才对齐。

## 样式精度

- CSS 每个属性**逐项对标参考源** — border-left 颜色、背景色、阴影，一项不能差。
- "跟人家的样式不一样" = 不合格。"差不多就行" = 重做。

## 行为准则

- **简单优先** — 能用 20 行不引框架，能用一个工具不组合三个。复杂度是负债。
- **出错就认** — 第一次明显失败就汇报，不静默重试，不编原因。
- **不编造确认** — "用户已确认"必须有输出证据。没看到文件/截图 = 没确认。
- **落盘才闭环** — 内存里的结论不算。文件能 `stat`、URL 能 `curl`、测试能过，才算做完。
